# Plan

Leave frees rooms. Adding leave releases any room held by the affected sessions, both at generation time (engine) and post-hoc on the active draft (API side effect). A new Phase 12 check surfaces the remaining cases the side effect deliberately does not touch (committed rotas, rollback-to-draft, forced edits). Removing leave never restores rooms — matching the existing WFH asymmetry; manual reassignment is easy.

# Scope

**In scope**
- Engine: Phase 2 skips the pre-occupancy room claim for on-leave slots.
- Engine: new Phase 12 warning `room_on_leave_slot`.
- API: `POST /leave` and `POST /leave/bulk` clear `room_id` on matching sessions of the active draft, in the same transaction as the insert.
- Frontend: leave mutation hooks invalidate the rota query cache; one label entry in the issues panel.

**Out of scope**
- Roles and `is_supervising` are never cleared. Phase 12's `role_on_incompatible_slot` and the two supervision checks (whose `is_eligible_supervisor` predicate already excludes on-leave slots) cover these cases as warnings. Clearing roles would drag clinic counters and duty semantics into the change.
- Leave removal does not restore rooms. No change to `DELETE /leave/{id}` or `POST /leave/bulk-delete` beyond the frontend cache invalidation (removal changes the derived `is_on_leave` rendering, so the rota view still needs a refetch).
- No undo path for the room-clearing side effect. Leave lives on its own page with no undo stack.
- Committed rotas are never mutated (draft-only edit invariant). The Phase 12 check plus `/issues` (which works on committed rotas) is how the consequence surfaces.

# Design Decisions

1. **Phase 2 skip is occupancy-only.** The on-leave slot is still created with its `template_type` and `template_room_id` intact; only the `grid.assign_room()` claim is skipped, so the room is free for Phases 5/7-9A and the persisted `RotaSession.room_id` is NULL. Phase 12's unresolved-room check already skips on-leave slots, so no warning noise. Phases 5, 7-9A, 9B and 9C already skip on-leave slots and need no changes; their "never displace an on-leave occupant" guards remain live for rebuilt grids (post-hoc leave on persisted rooms), so they are not dead code.
2. **New Phase 12 check `room_on_leave_slot`:** any slot with `is_on_leave=True` and `assigned_room_id` set, regardless of role. Never fires on a fresh generation after decision 1; fires only for post-hoc leave on committed rotas, a rollback-to-draft that reinstates a stale hold, or a forced `set-room` onto a leave slot via the API (the popover blocks this but apply-then-warn permits it). It can co-fire with `role_on_incompatible_slot` on the same slot — consistent with the existing "both supervision checks can fire at once" philosophy, not a duplicate.
3. **API side effect targets the active draft only,** found via `engine.generate.get_active_draft()`. No draft means no-op. Date-to-slot mapping reuses `week_map.build_week_dates()` + `build_date_to_genslot()` with the draft's config (`start_date` is guaranteed a Monday by Phase 0). Dates outside the draft range, weekends, and closed dates (no session row exists) all fall out as natural no-ops.
4. **Bulk clearing is idempotent-by-range:** rooms are cleared for every weekday candidate `(date, period)` pair in the request, including pairs skipped as duplicates. A duplicate means the leave already existed; clearing again is harmless if the room is already NULL and heals stale state (e.g. leave added before this feature shipped) if it is not.
5. **Same transaction as the insert.** The clearing runs before the router's `db.commit()`; an `IntegrityError` rollback undoes both. The existing endpoint-owns-transaction pattern is unchanged.
6. **Silent clearing.** Response schemas are unchanged — no released-room count. Phase 12 and the grid show the truth immediately.
7. **Single vs bulk period semantics:** `LeaveIn.period` is `Period` (AM/PM only — no BOTH literal), so the single endpoint clears exactly one `(date, period)`. Only `LeaveBulkIn` accepts `"BOTH"`, expanded via the existing `_expand_periods()`.
8. **Frontend invalidation by prefix:** the leave page does not know the draft's rota id, so all four leave mutation hooks additionally invalidate `rotaKeys.all` (`["rota"]`), covering detail, issues, and list queries. This is an exception to the rota page's splice-only philosophy, justified because the mutation originates on a different page with no response payload to splice from; navigating between pages already refetches on mount, this covers the multi-tab / stale-cache case.
9. **Issues panel:** `CHECK_LABELS` in `IssuesPanel.tsx` gains one entry for `room_on_leave_slot`. The panel already falls back to the raw check key for unknown checks, so this is cosmetic, not load-bearing.

# Task 3: API — leave endpoints release draft rooms

**A. State of the world.** Tasks 1 and 2 are complete: generation skips on-leave room claims and Phase 12 warns about any on-leave slot holding a room. This task makes `POST /leave` and `POST /leave/bulk` clear `room_id` on matching sessions of the active draft so leave added mid-draft frees the room immediately.

**Context required for the Sonnet chat:** the full current `backend/tests/test_api/test_leave_duty.py` must be pasted in — the project-knowledge copies are elided fragments. Also provide `backend/tests/test_api/conftest.py` (fixtures: `client`, `seeded`, `db_session`) and, if the seeded fixture does not already create a draft rota, whatever helper the rota API tests use to generate one.

**B. Files and deliverables.**
- `backend/app/api/routers/leave.py` — one module-private helper plus two call sites.
- `backend/tests/test_api/test_leave_duty.py` — new test class `TestLeaveFreesRooms`.

**C. Instructions.**
1. In `routers/leave.py`, add:
   ```python
   def _release_draft_rooms(
       db: Session, doctor_id: int, pairs: Iterable[tuple[datetime.date, Period]]
   ) -> None:
   ```
   Behaviour:
   - `draft = get_active_draft(db)` (import from `app.engine.generate`); return immediately if None.
   - Build the mapping once per call: `week_dates = build_week_dates(draft.config.start_date, draft.config.num_weeks)`, then `date_to_slot = build_date_to_genslot(week_dates)` (imports from `app.engine.week_map`).
   - For each `(date, period)` pair: look up `date_to_slot.get(date)`; if None (outside range / weekend), skip. Otherwise issue an UPDATE on `RotaSession` setting `room_id=None` where `rota_id == draft.id`, `doctor_id`, `week`, `day`, `period` match and `room_id IS NOT NULL`. A per-pair `db.execute(update(...))` loop is fine — N is small and it keeps the code obvious. **No commit inside the helper** — the caller owns the transaction.
2. Call sites:
   - `create_leave`: after `db.add(entry)` and before `db.commit()`, call `_release_draft_rooms(db, payload.doctor_id, [(payload.date, payload.period)])`. `LeaveIn.period` is AM/PM only, so no expansion needed.
   - `create_leave_bulk`: after the `candidates` list is built (it already contains every weekday `(date, period)` pair, duplicates included) and before the commit, call `_release_draft_rooms(db, payload.doctor_id, candidates)`. Deliberately pass all candidates, not just `to_insert` — see design decision 4. Keep the call outside the `if to_insert:` guard so an all-duplicates request still heals stale rooms; the commit inside that guard then needs restructuring so the release is committed even when nothing was inserted (simplest: hoist a single `db.commit()` to after the insert/release block, preserving the existing IntegrityError handling around it).
   - Delete endpoints: no changes.
3. Tests (`TestLeaveFreesRooms`), each generating or reusing a draft with a known session holding a room:
   - single `POST /leave` for AM clears that session's `room_id`; the same doctor's PM session keeps its room;
   - `POST /leave/bulk` with `"BOTH"` across a Mon–Fri range clears AM and PM rooms on every weekday in range; a range spanning a weekend is a clean no-op for the weekend days;
   - bulk request where every entry is a duplicate still clears a manually-set stale room (set `room_id` directly via `db_session` first);
   - a committed rota's sessions are untouched by a leave add covering its dates;
   - no active draft: `POST /leave` still returns 201 and no error;
   - a leave date outside the draft's range is a no-op;
   - `DELETE /leave/{id}` does not restore the cleared room.
