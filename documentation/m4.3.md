# M4.3 — Master Rota Template Editing (implementation plan)

## Scope

Make the currently read-only Master Rota tab editable, cell by cell, via a
popover menu — mirroring the M4.1 cell-edit pattern on the generated rota,
adapted to the much simpler master-session data model (`session_type` +
`room_id` only).

**In scope:**

1. Backend: `PATCH /api/v1/master-rota/templates/{template_id}/sessions/{session_id}`
   with server-side room displacement.
2. Frontend: `useUpdateMasterSession` hook, cache splice into the
   `useActiveMasterRota` query.
3. Frontend: `MasterCellEditPopover` (new component) with a five-option type
   menu, room submenus, and confirm-before-steal.
4. Page-level undo (single-level) + toast wiring on `MasterRotaPage`.
5. Grid rows derived from `/doctors` instead of the session payload
   (groundwork for M4.4).

**Out of scope (agreed during review):**

- **Drag-and-drop** on the master grid — cut entirely. The popover covers
  every operation; DnD swap semantics on a template are unclear and the cost
  (DndContext wiring, chips, `resolveMasterDrag`, a backend swap endpoint)
  is the largest item for the least value. Revisit only if actually missed.
- **Creating/deleting `MasterRotaSession` rows** (changing a doctor's
  working pattern, adding a new doctor's sessions, removing a leaver's) —
  deferred to **M4.4**, a named follow-up. Task 5 below deliberately
  prepares the grid for it.
- **No `issues` field in the response.** The undo/toast machinery does not
  consume issues (`onMutationApplied(entry, toastMessage)` carries none);
  returning a permanently empty array for shape compatibility was rejected.
  Response is `{ session, displaced_session }`.
- Phase 12 does not run on the template. The one genuine template-level
  conflict (same room pre-occupied twice in one slot) is handled by the
  displacement rule below, not by a validation pass.

## Context facts the implementer can rely on

- `MasterRotaSession`: `template_id, doctor_id, week, day, period,
  session_type, room_id` — unique on `(template_id, doctor_id, week, day,
  period)`. No status/draft concept: the template is live, and edits affect
  **future generations only** (RotaSession snapshots template_type at
  generation time — M3.6 — so existing drafts and committed rotas are
  untouched by design).
- `phase2._build_grid`: `PRE_ASSIGNED` and `ADMIN_TIME`-with-room
  pre-occupy their room from the start of generation
  (`_PRE_OCCUPYING_TYPES`); `REQUIRES_ROOM` is created unassigned;
  `NO_SURGERY`/`WFH` never hold a room. `ADMIN_TIME` with a room is real
  data (the seed contains "ADMIN TIME D7"), so the UI must be able to set
  and restore it.
- `GET /master-rota/active` returns `MasterRotaTemplateOut` with joined
  `doctor_code`/`doctor_type`/`room_code` per session; `MasterRotaTemplate.
  is_active` is not schema-enforced unique (endpoint orders by id, takes
  first).
- `pivotMasterRota` currently builds rows from doctors present in the
  session list — this changes in Task 5.

## Task 1 — Backend PATCH endpoint

`PATCH /master-rota/templates/{template_id}/sessions/{session_id}` on the
existing `routers/master_rota.py` router.

### Schemas (`schemas/master_rota.py`)

```
MasterSessionPatchIn:
  session_type: MasterSessionType   # required
  room_id: int | None               # required-present, nullable

MasterSessionPatchOut:
  session: MasterRotaSessionOut
  displaced_session: MasterRotaSessionOut | None
```

Both fields are always present (a verbatim pair setter, the same philosophy
as `set-role`'s verbatim triple) — this is what makes undo replay trivially
expressible as another PATCH.

`model_validator` on `MasterSessionPatchIn`, matching what phase2 actually
does with each type:

- `PRE_ASSIGNED`: `room_id` **required** (non-null).
- `ADMIN_TIME`: `room_id` optional.
- `REQUIRES_ROOM`, `NO_SURGERY`, `WFH`: `room_id` **must be null**.

### Router logic

1. 404 if the template doesn't exist; 404 if the session doesn't exist **or
   `session.template_id != template_id`** (scoping guard). The endpoint
   works on any template, active or not — the frontend only ever passes the
   active one, but there's no reason to hard-couple the endpoint to
   `is_active`.
2. 404 unknown `room_id` via an explicit lookup, not FK errors (which
   surface as 500s on Postgres at flush — the `set-room` precedent).
3. **Displacement** (only when `payload.room_id` is non-null): look up
   another `MasterRotaSession` in the same `(template_id, week, day,
   period)` — note: **not** same doctor — with `room_id ==
   payload.room_id`, excluding self. If found:
   - Displaced session's `room_id` → `None`.
   - If the displaced session's type is `PRE_ASSIGNED`, its type →
     `REQUIRES_ROOM`. (**Flagged assumption** — a `PRE_ASSIGNED` with no
     room violates the write-path invariant above and means nothing to
     phase2; `REQUIRES_ROOM` says "still works this session, room resolved
     at generation".) A displaced `ADMIN_TIME` keeps its type, room
     cleared — a valid state.
   - Same-slot-same-week only: the displacement lookup matches on the
     template `week` column, so a room held in week 1 does not displace a
     week 2 holder.
4. Write the payload pair verbatim to the target. Writing the same room the
   session already holds is a no-op for displacement (excluded by the
   excluding-self rule) and must not error.
5. Return `{session, displaced_session}` with the **same joined fields the
   GET produces** (`doctor_code`, `doctor_type`, `room_code`) — required or
   the frontend's `setQueryData` splice corrupts the cache shape. Factor
   the GET's per-session serialisation into a small shared helper rather
   than duplicating the join logic.
6. No counters touched, no Phase 12, no draft guard.

### Tests (`tests/test_api/test_master_rota.py`, extending the existing file)

- Happy path per type: set `NO_SURGERY` (room null), set `PRE_ASSIGNED` +
  room, set `ADMIN_TIME` with and without room, set `WFH`.
- 422s: `PRE_ASSIGNED` without room; `REQUIRES_ROOM`/`NO_SURGERY`/`WFH`
  with a room; missing field.
- 404s: unknown session, session belonging to a different template, unknown
  room.
- Displacement: same-slot holder loses the room; displaced `PRE_ASSIGNED`
  becomes `REQUIRES_ROOM`; displaced `ADMIN_TIME` keeps its type; a
  different-week holder is NOT displaced; self-assign of the current room is
  a no-op with `displaced_session: null`.
- Response contains joined `doctor_code`/`room_code` on both sessions.

This task is independently shippable — deployable with zero frontend change.

## Task 3 — `MasterCellEditPopover`

New component, a sibling of `CellEditPopover` (do not try to generalise the
existing one — the data models share nothing but the popover shell).

### Menu structure

Five mutually exclusive type options — **no WFH toggle** (rejected during
review: `session_type` is a five-value enum, a toggle has no defined
off-state):

1. **Normal clinic** → `requires_room`, room null. Direct, no submenu.
2. **Pre-assigned room** → submenu listing rooms → `pre_assigned` + room.
3. **Admin time** → submenu: **"No room"** entry at the top, then the room
   list → `admin_time` + room-or-null. (The submenu exists because
   ADMIN_TIME-with-room is real data that must be settable/restorable.)
4. **No surgery** → `no_surgery`, room null. Direct.
5. **WFH** → `wfh`, room null. Direct.

### Confirm-before-steal

Applies to any room pick (options 2 and 3 with a room): before sending,
check the in-memory session list for another session in the same
`(week, day, period)` of the **currently viewed week** holding that room.
If found, show the shared confirm view ("D1 is currently held by AB —
displace?") with Confirm/Cancel — the same client-side-advisory,
server-authoritative pattern `CellEditPopover` uses via `findRoomHolder`.
Cancel returns to the room submenu; nothing is sent. Extract or mirror the
holder-lookup from `slotConflict.ts` (a small `findMasterRoomHolder` over
`MasterRotaSession[]` — don't force the RotaSession-typed helper to serve
both).

Every cell with a session is editable — no leave concept, no committed
state on the template. (Absent cells stay inert until M4.4 adds create.)

### Tests (`MasterCellEditPopover_test.tsx`)

Menu renders five options; each direct option calls back with the right
pair; room submenus; Admin time "No room"; confirm appears only when the
room is held by another same-slot session; cancel sends nothing; confirm
passes the holder through.

## Task 4 — Page wiring: undo + toast

`MasterRotaPage.tsx` + `MasterRotaGrid.tsx`:

- **Make `useUndoStack` generic** over its entry type (`useUndoStack<T>`),
  with the existing rota `UndoEntry` union as the instantiation in
  `RotaDetailPage`. Do **not** grow the rota `UndoEntry` union or route
  master entries through `replayUndo.ts` (`buildReplayRequest` is
  rota-scoped, takes a `rotaId`). Master entry type, local to the master
  page or a small `masterUndo.ts`:

  ```
  interface MasterUndoEntry {
    sessionId: number;
    previous: { sessionType: MasterSessionType; roomId: number | null };
    displaced: {
      sessionId: number;
      sessionType: MasterSessionType;  // pre-displacement type
      roomId: number | null;
    } | null;
  }
  ```

  `previous`/`displaced` values are captured from the grid state at click
  time (the pre-mutation session objects), same as the rota entries.

- **Replay = 1–2 PATCH calls, displaced first, then target** (the
  `replayUndo` ordering convention). Restoring the displaced session to
  `PRE_ASSIGNED` + its room will itself auto-displace the target
  server-side — harmless, because the second PATCH then sets the target to
  its exact previous pair, overwriting the intermediate state. Serial
  execution; on failure, re-push the entry and show "Undo failed" (the
  Task 0 pattern).
- Mount `<Toast/>`; toast copy via a master-specific message helper (e.g.
  "AB Monday AM set to Pre-assigned D1", "Undone"). Undo button always
  rendered, disabled when the stack is empty (no layout shift — the
  M4.1 rule).
- **UI copy, one line under the page title:** "Changes apply to future
  generated rotas only." Replaces "Read-only template view." — without it,
  users will edit the template, look at the current draft, see nothing
  change, and assume the feature is broken.
- `MasterRotaGrid` gains `onMutationApplied`/`onMutationError` props and
  the popover trigger per cell, mirroring `RotaGrid`'s shape (minus
  everything drag-related).

### Tests

- `MasterRotaPage_test.tsx`: undo button state, toast on success, undo
  replays displaced-then-target, failed undo re-pushes.
- `MasterRotaGrid_test.tsx`: cells now open the popover; a successful edit
  reflects in the grid (via MSW + cache splice).
- `undoStack` test updates for the generic signature (behavioural tests
  unchanged).

## Task 5 — Grid rows from `/doctors` (M4.4 groundwork)

Change `pivotMasterRota` to take a `doctors: Doctor[]` argument and build
rows the way `pivotRota` does: active doctors (grouped by type,
alphabetical by code) **plus** any inactive doctor who has template
sessions, flagged `inactiveWithSessions`. `MasterRotaGrid` fetches
`useDoctors(false)` like `RotaGrid`.

Why now rather than in M4.4: it fixes a real display gap immediately (a
newly added doctor with zero template sessions is currently invisible on
this page), and it means M4.4's add-session work doesn't have to rework the
pivot a second time. A doctor row with no sessions renders empty cells
(inert until M4.4).

Tests: `pivotMasterRota_test.ts` rewritten for the new signature —
doctor-with-no-sessions gets a row; inactive-with-sessions flagged;
inactive-without-sessions dropped. `MasterRotaGrid_test.tsx` fixtures gain
the doctors fetch (MSW).

## Suggested implementation order

1 → 2 → 5 → 3 → 4. Task 1 ships alone; Task 5 before Task 3 so the popover
tests are written once against the final grid shape.

## Flagged assumptions (confirm or correct before coding)

1. **Displaced `PRE_ASSIGNED` becomes `REQUIRES_ROOM`** (room null);
   displaced `ADMIN_TIME` keeps its type with room null.
2. **Admin time gets a room submenu with a "No room" entry**, since
   ADMIN_TIME-with-room must be settable.
3. **`useUndoStack` is made generic** rather than duplicating the hook or
   growing the rota entry union.
4. Displacement matches within the same template `week` only.
5. Self-assigning a session's current room is a silent no-op (200,
   `displaced_session: null`), not an error.
