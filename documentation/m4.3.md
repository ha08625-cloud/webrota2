# Practice Closures (bank holiday weeks) — implementation plan

## Problem

Rotas can currently only be generated for standard weeks. Bank holiday
weeks need: no sessions on the closed date(s), no clinics scheduled there,
no duty expected there, secondary duty relocated to the first open weekday
of that week, and no spurious Phase 12 coverage warnings.

## Design decisions (confirmed with user)

1. **Secondary duty moves to the first open weekday** when Monday is
   closed (user: "it moves to Tuesday"). Implemented generically as
   "first open weekday of the week", which also handles a closed
   Mon+Tue pair and degrades to "no secondary expected" if a whole week
   is closed.
2. **Closed days render as greyed-out columns**, not removed columns.
3. **Closures are global planning data** (`practice_closures`), not a
   per-generation input — the Duty page must know about a closure weeks
   before any `RotaConfig` exists, so both the Duty page and the engine
   read the same table.
4. **Generation snapshots applicable closures onto the rota**
   (`rota_closures`), consistent with the M3.6 self-contained-snapshot
   principle: deleting a closure later must not rewrite how an existing
   draft/committed rota renders or validates.
5. **Phase 2 builds no slots on closed dates** (rather than building
   flagged slots). Downstream phases then need no per-slot closed checks;
   the frontend greys columns from the rota-level `closed_dates` list,
   not from slot data.
6. **Duty on a closed date is a Phase 0 error** (same tier as
   duty-on-leave: a pre-flight data error, not a generation tradeoff).
   The Duty page should prevent it, but the engine must not rely on that.

## Task 1 — Models + migration COMPLETE

- `PracticeClosure`: `id`, `date` (unique), `name` (nullable, e.g.
  "Easter Monday").
- `RotaClosure`: `id`, `rota_id` (FK `generated_rotas`, cascade delete),
  `date`; unique on `(rota_id, date)`.
- Migration `004_practice_closures.py`: both tables. Downgrade drops both.
- Tests: uniqueness constraints, cascade on rota delete
  (`tests/test_models.py` or a new file per existing convention).

## Task 2 — Closures API + settings page

- Router `closures.py`: `GET /api/v1/closures` (optionally
  `?from=&to=`), `POST /api/v1/closures`, `DELETE /api/v1/closures/{id}`.
  Reject non-weekday dates (weekends are never in the grid) with 422.
  Deleting a closure never touches `rota_closures` (snapshots are
  independent by design).
- Schemas `schemas/closure.py`; register router in `main.py`.
- Frontend: `api/closures.ts` hooks; a small Closures page (list + add
  date/name + delete), linked from the nav. No bulk UK-bank-holiday
  import in M5 — manual entry is a handful of dates per year; revisit if
  it annoys in practice.
- Tests: pytest router tests; vitest hook + page tests (MSW handlers).

## Task 3 — Engine changes

All keyed off `GenerationContext` gaining `closed_dates: frozenset[date]`
(loaded in `load_context()` from `PracticeClosure`, filtered to the run's
date range).

- **Phase 2**: skip building `SessionSlot`s whose `(week, day)` maps to a
  closed date. Leave/WFH on a closed date is irrelevant by construction.
- **Phase 0**: new error check `duty_on_closed_date` — any
  `duty_map` entry whose date is closed. (With Phase 0 blocking this,
  Phase 4's existing `duty_no_session_slot` warning never fires for
  closures.)
- **Phase 5**: skip a clinic schedule slot when its resolved date for
  that generation week is closed.
- **Phase 12**:
  - `_expected_duty_counts` becomes closure-aware: primary expected 0 on
    a closed day; secondary expected 1 per period on the **first open
    weekday of each generation week** (0 on all other days). Whole-week
    closure → 0 everywhere.
  - `clinic_coverage` skips schedule slots landing on closed dates
    (mirrors Phase 5).
  - Checks 3/4 need no change (no slots exist on closed dates).
- **`generate.py`**: `_write_to_db` writes `RotaClosure` rows for every
  closed date inside the generation range, in the same transaction.
- **`grid_utils.rebuild_rota_grid`**: read closed dates from
  `rota_closures` (the snapshot), not `practice_closures`, so post-hoc
  closure edits cannot change how `/issues` judges an existing rota.
- Tests (`tests/test_engine/`): factory `make_closure`; Phase 2 slot
  omission; Phase 0 duty-on-closed error; Phase 5 skip; Phase 12
  expected-count matrix (closed Monday → Tuesday secondary expected;
  open week unchanged; fully closed week); e2e in `test_generate.py`
  including `RotaClosure` snapshot rows written.

## Task 4 — Rota API surface

- `RotaOut` (and detail responses reusing it) gains
  `closed_dates: list[date]`, read from `rota_closures`.
- Generate request body unchanged — closures are picked up from the
  global table automatically; nothing for the user to re-enter.
- `run_phase12_for_rota` path (the `/issues` endpoint) covered via the
  Task 3 `grid_utils` change.
- Tests: `test_rota.py` — generate over a closed Monday returns the
  date in `closed_dates`; sessions absent for that day; no
  duty/clinic-coverage warnings for it.

## Task 5 — Frontend: grid rendering + Duty page

- `api/types.ts`: `Rota.closed_dates`.
- `RotaGrid`: grey out the full column for a closed day (cells inert —
  no popover, no drop target; same visual family as the existing
  grey/inert conventions). Column header may show the closure name if
  present.
- `dutyWeekSlots.ts`: takes the closure list; secondary slots attach to
  the first open weekday of the week; slots on closed dates are not
  emitted at all. `DutyGrid`/`DutyPage` render closed-day cells greyed
  and non-editable, and fetch closures via the Task 2 hook.
- `dutyWeekComplete.ts`: completeness derives from the (now
  closure-aware) required-slot list — verify no separate hardcoding.
- Tests: `RotaGrid_test.tsx` (greyed column, inert cells),
  `dutyWeekSlots_test.ts` rewritten for the new signature (closed
  Monday → 10 slots… recount: 4 open days x 2 periods primary = 8, +2
  Tuesday secondary = 10), `DutyPage_test.tsx`, MSW fixture updates.

## Task 6 — Docs and wrap-up

- Update `architecture.md` (new section: closures), `phase-pipeline.md`
  (Phase 0/2/5/12 amendments), domain model notes on the

- `ci.yml` unchanged (pytest/vitest auto-discover). No new dependencies

## Suggested order

1 (COMPLETE) → 3 → 4 → 2 → 5 → 6. Engine (3) before the closures UI (2): the engine
tests exercise the model directly and are the risk concentration;
the settings page is low-risk chrome.

## Flagged assumptions (confirm or correct before coding)

1. "First open weekday" is the correct generalisation of "moves to
   Tuesday" (covers Christmas-style multi-day closures).
2. Weekend closure dates are rejected at the API rather than silently
   ignored.
3. A closure added *after* a draft was generated does not retroactively
   affect that draft (snapshot semantics) — regenerate to pick it up.
4. The generate form needs no closure input at all; closures apply
   automatically when they fall in range. The rota detail page's greyed
   column plus header name is sufficient signalling.
5. Primary duty is simply not expected on closed days — it does not
   relocate the way secondary does.

## Review of plan
1. The grid-rebuild closure source needs a stated mechanism. rebuild_rota_grid() builds its context via load_context(db, config), and GenerationContext is a frozen dataclass. The plan says the rebuild path reads from rota_closures while generation reads practice_closures, but doesn't say how, given both go through load_context(). Specify one of: an optional closed_dates_override parameter on load_context(), or dataclasses.replace(context, closed_dates=...) inside rebuild_rota_grid() after loading. Without this, the likely failure mode is both paths silently reading practice_closures, which defeats Decision 4 and would only be caught if a test specifically deletes a closure post-generation. Add exactly that test: generate over a closure, delete the PracticeClosure, assert /issues output is unchanged.
2. The "first open weekday" rule will exist in two languages — pin it down. _expected_duty_counts(day) is currently day-only and must become week-aware (it needs gen_week, week_dates, and the closed set). The same rule is reimplemented in TypeScript in dutyWeekSlots.ts. This is the same situation as weightedScore.ts mirroring CounterState: acceptable, but the plan should say so explicitly and require mirror tests with the same case matrix on both sides (closed Monday, closed Mon+Tue, fully closed week, open week), so the two implementations can't drift.
3. Frontend date-to-column mapping is missing. RotaGrid currently has no date awareness, and date.ts has no (rota.start_date, closed_date) → (week, day) helper. Greying a column requires one — a small pure function mirroring week_map.py, with its own vitest file. Trivial, but it's an unlisted new file, and the plan's file inventory is otherwise complete.
4. Consider a 422 on the duty API too, not just the Duty page. The plan says "the Duty page should prevent it, but the engine must not rely on that." Elsewhere weekday-only is enforced as an API rule, not a UI rule (leave_entries). A duty POST for a closed date costs one query to reject and closes the direct-API gap; Phase 0 is still required regardless, because a closure can be added after a duty assignment already exists. Both layers, cheap.
