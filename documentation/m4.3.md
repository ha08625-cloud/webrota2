# Counter Reset — Implementation Plan

## Goal

Add the ability to reset counter values to zero from the Counters page: per-row reset and reset-all, for both clinic and system counters. Reset is a raw-count-to-zero update, never a row delete, so the snapshot/scrap lifecycle and the engine's lazily-created / new-this-run logic are untouched.

## Confirmed design decisions

1. **Reset updates `raw_count` to 0 and never deletes rows.** Row identity (`(doctor_id, clinic_type_id)` / `(doctor_id, counter_type)`) is preserved, so scrap's key-based restore/delete logic is undisturbed.
2. **No draft-lifecycle gating in the backend.** Reset is allowed unconditionally. It is already safe with respect to scrap: scrap restores every snapshotted value regardless of what caused the drift, so a mid-draft reset is reverted by scrap like any other manual edit.
3. **Reset-all resets every row in the table, not just the Partner/Salaried rows the page displays.** Counter rows can exist for Trainees/AHPs (system counters are seeded per active doctor; clinic counters are lazily created for any doctor a clinic's eligibility reaches). A partial reset would leave invisible non-zero counters skewing Phase 5/9C tie-breaks against zeroed visible ones. The confirmation text must state this explicitly.
4. **All four endpoints are POST action endpoints**, matching the codebase convention (`swap-roles`, `set-room`, `commit`), not PATCH.
5. **Confirmation is `window.confirm`**, matching every other destructive confirm in the app. The draft warning is composed into the confirm string.
6. **Draft-warning wording (frontend):** the warning must say that scrapping the draft will *undo* the reset, i.e. restore pre-generation values. It must NOT imply scrap "corrects" counters toward the reset. Canonical text is given in Task 3.
7. **Single reset returns the updated `ClinicCounterOut`/`SystemCounterOut` (same joined shape as GET). Reset-all returns 204 No Content** — the frontend invalidates and refetches, so returning the list is redundant.
8. **Unknown id on single reset is 404** via explicit lookup.
9. **Auth:** existing `get_current_user` shim only. There is no role concept in this app; anyone with the token can reset. Accepted.

## Endpoint summary

| Method | Path | Behaviour | Response |
|---|---|---|---|
| POST | `/counters/clinic/{counter_id}/reset` | Set that `ClinicCounter.raw_count = 0` | 200, `ClinicCounterOut` |
| POST | `/counters/system/{counter_id}/reset` | Set that `SystemCounter.raw_count = 0` | 200, `SystemCounterOut` |
| POST | `/counters/clinic/reset-all` | `UPDATE clinic_counters SET raw_count = 0` (all rows) | 204 |
| POST | `/counters/system/reset-all` | `UPDATE system_counters SET raw_count = 0` (all rows) | 204 |

Route-ordering note: FastAPI matches in registration order; register `reset-all` routes before the `{counter_id}` routes (or rely on `counter_id: int` path typing rejecting `"reset-all"` — registering reset-all first is the belt-and-braces convention to follow here).

No new schemas: single-reset responses reuse `ClinicCounterOut`/`SystemCounterOut`, which requires the reset handler to join doctor code (and clinic type name) exactly as the GET handlers do.

## Task 4 — Frontend: CountersPage UI

**State of the world:** Hooks and MSW handlers exist (Task 3). This task adds the reset buttons, confirmations, and the draft-aware warning to the page, plus its tests. This is the final task.

**Files to read:**
- `frontend/src/routes/CountersPage.tsx` (the file being edited)
- `frontend/src/routes/CountersPage.test.tsx`
- `frontend/src/api/counters.ts` (Task 3 hooks)
- `frontend/src/api/rota.ts` (`useRotaList`) and `types.ts` (`RotaSummary.status`)
- `frontend/src/routes/RotaDetailPage.tsx` (window.confirm usage for destructive actions)

**Deliverables:** updated `frontend/src/routes/CountersPage.tsx`, updated `frontend/src/routes/CountersPage.test.tsx`.

**Instructions:**
1. Call `useRotaList()` in the page. `const draftActive = (rotas ?? []).some((r) => r.status === "draft")`. If the rota list is loading or errored, treat `draftActive` as false and fall through to the generic warning — do not block resets on rota-list availability.
2. Draft warning composition. Base confirm messages:
   - Single: `Reset this counter to 0? This cannot be undone.`
   - All clinic: `Reset ALL clinic counters to 0, including counters for doctors not shown on this page? This cannot be undone.`
   - All system: same wording for system counters.
   When `draftActive`, append: ` Note: a draft rota is currently active. If that draft is scrapped, all counters will be restored to their pre-generation values and this reset will be undone. To make the reset permanent, commit or scrap the draft first.`
   Do not use wording implying scrap "corrects" or "fixes" counters.
3. UI: a small "Reset" button in a new trailing column on each row of both tables, and a "Reset all clinic counters" / "Reset all system counters" button next to each table's heading. Follow the page's existing Tailwind styling; destructive styling consistent with other destructive buttons in the app. Disable buttons while the corresponding mutation `isPending`.
4. Each click: `window.confirm` with the composed message; on accept, fire the mutation. Surface mutation errors the same way other pages do (if the repo has no established inline-error pattern for mutations on this page, a simple error line under the heading is acceptable — match `clinicError` styling).
5. Update the page subtitle: the current copy frames the page as a pure view; extend it to mention that counters can be reset here.
6. Tests (extend `CountersPage.test.tsx`, mocking `window.confirm` via `vi.spyOn`):
   - Reset button per row renders; clicking with confirm-accepted fires the single-reset request (assert via MSW handler); confirm-cancelled fires nothing.
   - Reset-all button fires the bulk request on accept.
   - Confirm message includes the draft warning when the rota list contains a draft (stub the `/api/v1/rota` handler), and excludes it when there is no draft.
   - The "including counters for doctors not shown on this page" wording appears in the reset-all confirm.
