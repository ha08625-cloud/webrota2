## Duty Counter Display — Provisional Plan

### Summary

Add a `GET /duty/counts` endpoint that derives a per-doctor duty session count directly from the `duty_assignments` table via a LEFT OUTER JOIN + GROUP BY. No migration, no new stored counter. Display raw count and weighted score in fixed-width columns to the right of each doctor chip in DutyGrid's left palette.

---

### Design decisions

**No stored counter.** The count is always exactly derivable from `duty_assignments`. A stored counter would require snapshotting, a migration to extend `SystemCounterType`, and decisions about whether scrap/commit affects it. None of that is warranted here.

**Invalidation is free.** `useCreateDuty` and `useDeleteDuty` both already call `queryClient.invalidateQueries({ queryKey: dutyKeys.all })`. If `useDutyCounts` is keyed under `["duty", "counts"]`, it gets invalidated automatically whenever an assignment is added or removed. No hook changes needed beyond adding the new query.

**All active doctors, not just Partner/Salaried.** The endpoint returns all active doctors (0-count or otherwise). DutyGrid's palette already filters to Partner/Salaried for drag purposes; the count lookup is just a Map keyed by `doctor_id`, so the typing mismatch is invisible to both layers.

**Weighted score computed client-side.** DutyGrid already holds `doctorsById: Map<number, Doctor>` and Doctor carries `sessions_per_week`. The existing `computeWeightedScore` / `formatWeightedScore` utilities from `lib/weightedScore.ts` are reused directly — no duplication.

**No route conflict.** The duty router has no `GET /{duty_id}` (only `DELETE /{duty_id}`), so `GET /counts` will not be shadowed by a parameterised route.

### Task 1 — Backend: `DutyCountOut` schema + `/duty/counts` endpoint

**Files:**
- `backend/app/api/schemas/duty.py` — add `DutyCountOut` (note: this file is missing from project files — provide before implementing)
- `backend/app/api/routers/duty.py` — add `GET /counts`
- `backend/tests/test_api/test_leave_duty.py` — tests

**`DutyCountOut`:**
```python
class DutyCountOut(BaseModel):
    doctor_id: int
    doctor_code: str
    raw_count: int
    sessions_per_week: Decimal  # serialised as string on the wire, matching DoctorOut
```

**Endpoint:**
```
GET /api/v1/duty/counts
```
LEFT OUTER JOIN `doctors` → `duty_assignments` on `doctor_id`, grouped by `(doctor.id, doctor.code, doctor.sessions_per_week)`, filtered to `active = true`, ordered by `doctor.code`. Returns all active doctors, 0 where no assignments exist.

**Tests:**
- All active doctors returned with `raw_count = 0` when no assignments exist
- Count reflects actual assignments per doctor
- Inactive doctors excluded
- Doctor with assignments in multiple dates counts all of them (not just distinct dates — each assignment row is one session)

### Task 2 — Frontend: type, hook, DutyGrid layout

**Files:**
- `frontend/src/api/types.ts` — add `DutyCount`
- `frontend/src/api/duty.ts` — add `useDutyCounts()` and `counts` key
- `frontend/src/components/DutyGrid.tsx` — fetch counts, render alongside chips

**`DutyCount` type:**
```typescript
export interface DutyCount {
  doctor_id: number;
  doctor_code: string;
  raw_count: number;
  sessions_per_week: string; // Decimal on the wire
}
```

**Hook:**
```typescript
export const dutyKeys = {
  all: ["duty"] as const,
  list: () => [...dutyKeys.all, "list"] as const,
  counts: () => [...dutyKeys.all, "counts"] as const,
};

export function useDutyCounts() {
  return useQuery({
    queryKey: dutyKeys.counts(),
    queryFn: () => apiClient.get<DutyCount[]>("/duty/counts"),
  });
}
```

**DutyGrid layout change:**

The left panel widens from `w-40` to `w-56`. Small column headers (`n` / `wtd`) are added at the top of the panel, right-aligned. Each chip row becomes a flex row:

```
[chip — flex-1]   [raw — w-8 text-right]   [weighted — w-10 text-right]
```

`tabular-nums` on both count spans for digit alignment. If counts are loading or a doctor is not in the map yet, render `—` (en-dash) in both positions. Weighted score uses the existing `computeWeightedScore(count.raw_count, doctorsById.get(d.id))` — the `doctorsById` map is already present in DutyGrid.

**Tests:**
- Raw count and weighted score render beside each chip once counts resolve
- Correct values for a doctor with known assignment count
- Graceful fallback (`—`) when counts query is still loading
